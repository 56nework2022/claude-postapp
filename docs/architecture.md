## 1. テクノロジースタック

LINE版と同一の構成を踏襲する。

| 分類 | 採用技術 | 備考 |
|---|---|---|
| フレームワーク | Flutter(Dart) | iOS / Android 両対応の単一コードベース |
| 状態管理 | flutter_riverpod `^2.6.1` | Notifier/Providerベースで画面ごとの編集状態を管理 |
| ローカルデータ保存 | hive `^2.2.3` / hive_flutter `^1.1.0` | 端末ローカルのみ。クラウド不使用・オフライン完結 |
| コード生成 | hive_generator `^2.0.1` / build_runner `^2.4.13`(dev) | Hiveアダプタの自動生成に使用 |
| 画像書き出し | screenshot `^3.0.0` | 表示中Widgetをキャプチャし、PNGとしてカメラロールへ保存 |
| カメラロール保存 | gal `^2.3.3` | 導入時点でメンテナンスが活発なため採用 |
| アイコン画像選択 | image_picker `^1.2.3` | アカウントアイコンの端末内画像選択に使用 |
| フルスクリーン制御 | Flutter標準 `SystemChrome` API | `SystemUiMode.immersiveSticky` 等でOSのシステムUIを隠す |

- 外部サービス・バックエンドAPI・クラウド同期は一切使用しない(`functional-design.md` 8節参照)
- バージョンは2026-08-02時点で `flutter pub add` により解決された最新安定版を `pubspec.yaml` に固定したもの

- **開発支援ツール:** Claude Code を活用した実装・レビューを行う

## 3. 技術的制約と要件

### 3.1 プラットフォーム制約

- iOS / Android の両OSに対応する
- ステータスバーはiPhone風/Android風の2種類のレイアウトを切り替えられる構造とする(OS実機のステータスバーではなく、アプリ側で描画した疑似ステータスバーを使用)

### 3.2 データ・通信制約

- 端末ローカル保存(Hive)のみを使用し、クラウド同期・外部通信は行わない
- ユーザー登録・ログイン機能は持たない(即起動・即利用を優先)
- 課金管理はApp Store / Google Playの課金基盤に委ねる(独自の決済・サーバー処理は持たない)

### 3.3 知的財産権に関する制約

- Xは実在サービスであるため、公式ロゴ・正確な名称の使用は避け、「X風」の表現にとどめる
- UIパーツ(アイコン等)はXの公式アセットを流用せず、独自にそれらしいビジュアルを実装する
- 本制約は法務確認が完了するまで暫定方針として扱う

### 3.4 撮影運用上の制約

- 撮影用スマホ1台にアプリをインストールし、そのまま実機の画面を役者に持たせて撮影する「1台完結」運用を前提とする
- 撮影中にOSの通知・システムUI(ステータスバー・ホームバー)が一切表示されないことを必須要件とする

## 4. パフォーマンス要件

- **フルスクリーン表示への遷移:** エディタからフルスクリーン表示モードへの切り替えは体感的な遅延なく(即時に)行われること。撮影本番中の操作であるため、ロード待ちが発生しないようにする
- **システムUIの非表示維持:** フルスクリーン表示中、OSのジェスチャー操作等によってシステムUIが再表示されないよう `immersiveSticky` モード等で維持すること
- **タイムライン描画:** 投稿件数が増えてもスクロールがカクつかないよう、リスト表示は遅延構築(`ListView.builder` 相当)を用いる
- **画像書き出し:** 書き出し操作から保存完了までの待ち時間を最小限に抑え、待機中であることが分かるフィードバック(ローディング表示等)を用意する
- **起動時間:** クラウド通信を行わないため、起動から操作可能になるまでの時間はローカルI/O(Hive読み込み)のみに依存する。プロジェクト数が増えても起動が遅延しないようにする
