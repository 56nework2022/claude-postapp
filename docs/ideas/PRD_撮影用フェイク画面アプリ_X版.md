# プロダクト要求仕様書(PRD)
## 撮影用ポスト画面メーカー

> **ステータス:** ドラフト v0.1
> **最終更新:** 2026-08-01
> **関連プロダクト:** 撮影・演劇用フェイク画面メーカー(LINE版)と同一シリーズ

---

## 1. 背景・課題

映画・ドラマ・演劇などの映像/舞台制作において、登場人物がX(旧Twitter)を使う場面を撮影したいニーズがある。しかし実物のXアプリでは、投稿内容・いいね数・リポスト数・日時・アカウント名・アイコンなどを自由にコントロールできず、撮影現場での再現が難しい。

本アプリは、**撮影用スマホの実機画面にリアルなX風フェイク画面を表示**し、制作者が投稿や画面を自由に作り込めるようにすることで、この課題を解決する。

LINE版と同一シリーズのアプリとして、同じターゲット・同じ思想で開発する。

---

## 2. ターゲットユーザー

- **メイン:** 映画・ドラマ・自主制作映画・演劇などの制作スタッフ(小道具担当、美術、監督、撮影部など)
- **サブ(想定):** YouTube・ショート動画などの個人クリエイター、写真作品の制作者

特に**アマチュア映画制作者・学生・コストを抑えたい制作現場**を重点ターゲットとする。

---

## 3. プロダクトコンセプト

> **「撮影現場で、本物そっくりのX画面を、実機にそのまま表示できるアプリ」**

LINE版と同様に、単なる画像生成ではなく**実機表示(現場でのライブ運用)**を主目的とする。撮影用スマホ1台にアプリを入れて、そのまま役者に持たせて画面を映す、1台完結の運用を前提とする。

---

## 4. 提供価値

- 投稿内容・いいね数・リポスト数・日時・アカウント名・アイコンを自由に作り込める
- ステータスバー(時刻・電波・電池)まで含めて画面全体が本物に見える
- 撮影中に通知やホームバーが映り込まないフルスクリーン表示ができる
- 1つの作品(プロジェクト)に複数の画面を持たせ、撮影中に切り替えられる
- 作った画面を画像として書き出し、スタッフへの連絡・資料作りにも使える

---

## 5. 再現する画面の種類とフェーズ分け

LINEと異なり、Xは構造が異なる複数の画面タイプが存在する。撮影での登場頻度と作りやすさでフェーズ分けする。

### フェーズ1(MVP)
- **投稿詳細画面** — 1つの投稿をドアップで表示。いいね・リポスト・返信数・日時を設定可能。「この投稿が物語のキーになる」シーンで使いやすい。撮影での登場頻度が最も高い
- **タイムライン画面** — 複数の投稿が縦に並ぶフィード画面。「SNSをチェックする」シーンの定番
- 撮影用フルスクリーン表示モード
- ステータスバー設定(時刻・電波・電池・iPhone/Android切り替え)
- アカウント設定(名前・ユーザー名・アイコン・認証バッジの有無)
- プロジェクトの複数保存・呼び出し
- 画像書き出し

### フェーズ2
- **プロフィール画面** — アカウントのプロフィール・フォロワー数・投稿一覧。「この人物のアカウントを調べる」シーンなど

### フェーズ3
- **DM画面** — ダイレクトメッセージのトーク画面(チャット型)。LINE版との使い分けを見てから判断

---

## 6. アーキテクチャ方針

### 6.1 画面の構造タイプ

Xの画面はLINEと異なり**フィード型**が中心。構造の違いを整理する:

- **フィード型(今回のメイン):** タイムライン・投稿詳細・プロフィール — 投稿にいいね・リポスト・コメントがぶら下がる構造
- **チャット型(フェーズ3):** DM — LINEと近い吹き出し構造。フェーズ3で別エディタとして実装

### 6.2 データ階層

```
アプリ(1本)
 └─ プロジェクト(作品)※複数保存可能
     └─ 画面(Scene) ※1プロジェクトに複数持てる
         例:タイムライン / 投稿詳細 / プロフィール / DM
```

### 6.3 操作:テンプレート先行方式

新規作成時にまず「何を作るか(タイムライン / 投稿詳細 / プロフィール…)」を選ばせ、選んだ種類専用の編集画面だけを表示する。ユーザーは常に「自分が選んだ1種類分」の操作だけを見る。

- フェーズ1(投稿詳細+タイムライン)で単一アプリとしてリリースし、市場の反応を見る

## 8. 収益化モデル

LINE版と同じ方針を踏襲する。

**基本方針:フリーミアム(核機能は完全無料 + 追加機能は買い切り)**

「お金がない人ほど使ってほしい」という価値観を最優先。高額サブスクは採用しない。

**無料(透かしなし):**
- 投稿詳細画面・タイムライン画面の作成
- 実機フルスクリーン表示
- 画像書き出し
- プロジェクトの複数保存
- ※ フェーズ1一式を無料とし、撮影に不自由しない体験を担保する

**買い切り(追加機能):**
- プロフィール画面・DM画面などフェーズ2以降の画面
- 高度な演出機能
- 価格帯: TBD

**ウォーターマーク(透かし)の方針:**
- 実機表示・画像書き出しともに無料でも透かしなし(撮影に映り込むため)

## 9. 制約・前提

- **知的財産権:** Xは実在サービス。ロゴや正確な名称をそのまま使うと商標・著作権上の問題が生じうる。「X風」にとどめ、公式ロゴ・正確な名称の使用は避ける方針とする(要法務確認)
- **対応OS:** iOS / Android の両対応。ステータスバーのレイアウトはiPhone/Android表示を切り替えられる構造とする
- **撮影実機への表示方法:** 撮影用スマホ1台にアプリを入れ、そのまま画面を見せる1台完結の運用を前提とする
- **ユーザー登録・アカウント機能:** 不要。ダウンロード→即起動→すぐ使える体験を最優先。課金管理はApp Store / Google Playに委ねる
- **開発体制:** ひとり開発。スケジュール・予算は現時点では未定

## 10. 成功指標(KPI)

LINE版と同じ優先順位:

1. **ダウンロード数** — とにかく使ってもらえたか

4. **レビュー・口コミの質** — 現場で本当に役立ったかの定性指標

具体的な数値目標は、リリース後の状況を見て設定する。

```
# 撮影・演劇用フェイク画面メーカー X版 アプリ開発

## プロジェクト概要

映画・ドラマ・演劇などの撮影現場で、スマホの実機画面にリアルなX(旧Twitter)風のフェイク画面を表示するFlutterアプリを開発する。スクリーンショット生成ツールではなく、「撮影用スマホ1台に入れて、そのまま役者に持たせて画面を映す」実機表示ツールが主目的。

## 技術スタック

- Flutter / Dart(iOS・Android 両対応)
- データ保存: 端末ローカルのみ(hive を使用)
- 外部サービス・クラウド: 不使用
- 状態管理: Riverpod

## アーキテクチャ方針

**共通インフラ + 種類別エディタ**の構造で作る。

- 共通インフラ: アカウント管理・ステータスバー設定・フルスクリーン表示・画像書き出し・プロジェクト保存
- 種類別エディタ: タイムライン・投稿詳細・プロフィール・DMをそれぞれ別ウィジェットで実装。フェーズ1はタイムラインと投稿詳細のみ
- 新規作成時に「何を作るか」を先に選ばせるテンプレート先行方式

**データ階層:**
```
プロジェクト(Project)
 └─ 画面(Scene) ※複数持てる
     └─ 種類(type: timeline / post_detail / profile / dm)
     └─ アカウントリスト(Account[]) ※名前・ユーザー名・アイコン・認証バッジ
     └─ 投稿リスト(Post[]) ※本文・いいね数・リポスト数・返信数・日時
     └─ ステータスバー設定(StatusBarConfig)
```

## フェーズ1(MVP)のスコープ ← まずここだけ作る

以下のみ実装する。それ以外は後回し。

1. **プロジェクト一覧画面** — プロジェクトの作成・一覧表示・削除。hiveでローカル保存
2. **画面一覧画面** — プロジェクト内の画面(Scene)を複数管理。新規作成時に種類を選ぶ(フェーズ1はタイムライン・投稿詳細のみ)
3. **アカウント設定** — 名前・ユーザー名(@xxx)・アイコン画像・認証バッジ(あり/なし)を設定
4. **ステータスバー設定** — 時刻(任意入力 or 現在時刻)・電波・電池・iPhone/Android切り替え
5. **投稿詳細エディタ** — 1つの投稿の本文・いいね数・リポスト数・返信数・日時を設定。引用ポストにも対応できると尚良い
6. **タイムラインエディタ** — 複数の投稿を縦に並べて管理。投稿の追加・編集・並び替え
7. **撮影用フルスクリーン表示モード** — システムUI(ステータスバー・ホームバー・通知)を完全に隠し、アプリ描画で上書き
8. **画像書き出し** — 現在表示中の画面をPNG画像としてカメラロールに保存

## 重要な設計上の注意点

- **フルスクリーン表示が最重要**: `SystemChrome.setEnabledSystemUIMode(SystemUiMode.immersiveSticky)` を使い、OSのステータスバーを完全に隠してアプリ側で描画したステータスバーで上書きする
- **透かし(ウォーターマーク)は一切入れない**: 無料版でも透かしなし
- **iPhone/Android表示の切り替え**: ステータスバーのレイアウトをiPhone風/Android風で切り替えられるウィジェットを共通化する
- **Xの公式ロゴ・名称は使わない**: 「X風」にとどめ、公式ロゴや正式名称は使用しない
- **数値の自由設定**: いいね数・リポスト数などは自由に入力できること(「1.2万」のような表記も設定できると良い)

## 最初にやってほしいこと

1. Flutterプロジェクトを作成し、hive・Riverpod・`screenshot`パッケージ(画像書き出し用)を導入する
2. 上記データ階層のモデルクラス(Project / Scene / Account / Post / StatusBarConfig)を作成する
3. プロジェクト一覧画面から始めて、画面一覧 → エディタ → フルスクリーン表示の順で実装を進める
4. 各ステップで実機(またはシミュレータ)で動作確認しながら進めること
```
